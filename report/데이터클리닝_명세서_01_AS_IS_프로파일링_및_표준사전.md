## 1. 개요 및 AS-IS 원천 데이터 현황

### 1.1 프로파일링 목적
현업 레거시 EMR 환경을 재현한 대용량 원천 데이터(17종, **1,152만 행**)를 대상으로 Pandas 및 SQL 기반 전수 프로파일링을 수행하여 **결측·중복·형식 불일치·코드값 혼용·부모키 참조 부정합** 등 현행(AS-IS) 품질 문제를 수치로 진단하고, 이를 해결하기 위한 **AI 데이터 표준 사전**을 수립한다.

### 1.2 원천 테이블 및 1·2차 정제 후 행 수 현황
- **원천 전체 규모 (Bronze)**: 17개 테이블 총 **`11,522,242행` (약 1,150만 건)**
- **1차 정제 후 (`10/14` DB 적재)**: Clean `9,981,313행` (약 1,000만 건) / 1차 격리·제외 `1,540,929행`
- **2차 부모키 연쇄 격리 후 (`10/15` 최종 DB)**: `reclean_quarantine`에 **약 260만~280만 행 추가 연쇄 격리** ➔ 전체 원천 대비 **약 `38.4%`(약 440만 건) 격리 보존**, 최종 Clean 약 `710만 행` 확정.

## 2. AS-IS 4대 핵심 품질 결함 수치 진단

### 2.1 결함 1: 센티널(더미) 외래키 및 부모-자식 참조 무결성 붕괴 (38.4% 격리 원인)
- **진단 수치**:
  - `HDP_999999999`, `SES_999999999`, `DOC_999999999` 등 마스터에 존재하지 않는 더미 키 및 미등록 부모키 참조 다수 발견.
  - 특히 `encounters`가 상위 `checkin_id` 결함으로 격리(`202,474건`)될 때, 하위 `payments`(`671,532건`)와 `encounter_services`(`874,947건`)가 고아 레코드(Orphan)로 남는 **연쇄 부정합(Cascade Defect)** 확인.
- **조치**: 부모키가 격리된 하위 수납·처방을 합산하면 유령 매출 및 가짜 미수금이 발생하므로, `reclean_quarantine` 테이블로 연쇄 격리하여 100% 참조 무결성 확보.

### 2.2 결함 2: PK 중복, 포맷 불일치 및 음수/부호 오염
- **진단 수치 (`payments` 1,507,501행 기준)**:
  - PK(`payment_id`) 완전 중복: **`7,501건`** (`payments_excluded`로 분리)
  - 하이픈(`-`) 혼용 ID (`PAY-0001` vs `PAY_0001`), 공백 포함 문자열, 금액 컬럼 내 화폐 기호(`₩`) 및 쉼표(`,`) 혼입, 음수 결제액/환불 부호 혼용 등 **`88,006건`** 1차 격리.

### 2.3 결함 3: 진료 시간대 생성 범위 편중 (`08:00 ~ 14:59`)
- **진단 수치 (최종 `encounters` 496,863건 기준)**:
  - 진료 시작 시각(`started_at`)이 24시간이 아닌 **`08:01:30 ~ 14:59:42` (08시~14시)** 구간에만 존재 (15시~익일 07시 0건).
  - **09시~13시(5시간)**에 전체 진료의 **`83.5%`(414,860건)** 집중, **08시**는 분할결제율 **`60.45%`** 최고치, **14시**는 환불 발생률 **`16.25%`** 최고치.
- **도메인 해석**: 실제 종합병원의 오전 외래 집중(75~80%), 아침 선수납/검사 분할결제(08시), 오후 퇴원·취소 환불 정산 마감(14~15시) 피크 타임 특성을 반영한 데이터로 해석.

### 2.4 결함 4: 병원·진료과·월별 지표의 균등 분포 (Critical Finding ➔ 분석 피벗)
- **진단 수치**:
  - 최종 정상 진료 `496,863건`에서 금액 차액·결제 누락·보류가 **모두 `0건` (일치율 `100.0%`)**.
  - 485개 병원, 12개 진료과, 36개월 코호트 간 분할결제율(`~37.86%`)과 환불률(`~9.56%`)의 편차가 거의 없는 균등 분포(Cramér's V < 0.001).
- **분석 전략 피벗**:
  - 데이터에 없는 '병원 간 오류 순위'를 억지로 만들지 않고, **「100% 정상 대사 결과 제시 + 분할결제(37.86%)·환불(9.56%)의 합산 확인 규모 규명 + 업무 복잡도 시나리오(+124.1%) 실험」**으로 분석 주제를 정립.

## 3. AI 데이터 표준 사전 (AI Data Standard Dictionary)

전체 17개 테이블 119개 컬럼에 대한 상세 표준 사전은 [`원본명세기반119개컬럼표준사전.csv`](../medallion_hopitalData/원본명세기반119개컬럼표준사전.csv)에 정의되어 있으며, 수납·진료 대사 핵심 표준은 다음과 같다.

### 3.1 핵심 표준 용어 및 컬럼 규격

| 테이블명 | 물리 컬럼명 | 논리 한글명 | 표준 데이터 타입 | NULL 허용 | 표준 도메인 및 허용값 규칙 |
| :--- | :--- | :--- | :--- | :---: | :--- |
| `encounters` | `encounter_id` | 진료식별자 | `VARCHAR(30)` | NO | PK, `ENC_` + 9자리 숫자 (`^ENC_[0-9]{9}$`) |
| `encounters` | `gross_charge` | 총진료비 | `BIGINT` | NO | `>= 0`, 처방(`encounter_services`) 합계와 대사 |
| `encounters` | `authorized_refund`| 승인환불액 | `BIGINT` | NO | `0 <= authorized_refund <= gross_charge` |
| `encounters` | `net_charge` | 순청구액 | `BIGINT` | NO | `gross_charge - authorized_refund` 일치 필수 |
| `payments` | `payment_id` | 거래식별자 | `VARCHAR(30)` | NO | PK, `PAY_` + 9자리 숫자 (`^PAY_[0-9]{9}$`) |
| `payments` | `transaction_type` | 거래유형코드 | `VARCHAR(20)` | NO | `PAYMENT`(결제), `REFUND`(환불) 외 금지 |
| `payments` | `payment_method` | 결제수단코드 | `VARCHAR(20)` | NO | `CARD`, `CASH`, `BANK_TRANSFER`, `MOBILE` |
| `payments` | `amount` | 거래금액 | `BIGINT` | NO | 양수 정수(`> 0`), 환불도 양수로 기록 후 차감 계산 |
| `payments` | `original_payment_id`| 원결제식별자 | `VARCHAR(30)` | YES | `REFUND` 시 선행 `PAYMENT` PK 필수, `PAYMENT`는 NULL |
