# 외래 EMR 데이터 분석 프로젝트

> **자원은 충분한데 병원은 왜 멈추는가?**
> 데이터 기반 의료 자원 불균형 해소 및 외래 프로세스 개선

외래 EMR의 예약·접수·진료·수납 데이터를 정제하고 연결해, 환자의 진료 과정과 병원 운영을 네 가지 관점에서 분석하는 팀 3 프로젝트입니다.

## 1. 개요

### 1.1 프로젝트 배경과 목적

병원 운영을 이해하려면 의료기관·의료진의 규모뿐 아니라 환자가 언제 도착하고, 진료와 수납으로 어떻게 이어지는지도 함께 살펴봐야 합니다. 원천 시스템별로 분산된 기록과 단계별로 분리된 집계만으로는 외래 전 과정의 문제를 파악하기 어렵습니다.

이 프로젝트는 병원 기준정보부터 예약, 접수, 진료, 결제·환불까지 연결되는 데이터를 바탕으로 **운영 현황을 정량적으로 파악하고 우선 점검할 범위와 개선 방향을 제안**하는 것을 목적으로 합니다.

### 1.2 대주제와 네 가지 분석 관점

**대주제: 데이터 기반 의료 자원 불균형 해소 및 외래 프로세스 최적화**

| 관점 | 소주제 | 확인할 내용 | 개선 검토 방향 |
| --- | --- | --- | --- |
| 인프라 | 레거시 원천 시스템 A/B 품질 비교와 통합 | 시스템별 품질 차이, 교차 이용 환자, 기준정보의 일관성 | 환자·코드 기준정보 통합과 검증 |
| 접수 | 진료과·시간대별 현장접수 불가 패턴 분석을 통한 사전 방문 안내 개선 | 접수불가 규모·비율·시간대별 차이와 반복성 | 발생 규모가 큰 반복 구간의 접수 정책·사전 안내 점검 |
| 진료 | 병원별 환자 밀집도 분석을 통한 의사 진료 배치 최적화 | 병원·진료과별 환자 규모와 의사 배치의 편차 | 의료 자원 배치 대안 검토 |
| 수납 | 진료 후 결제·환불 패턴 분석을 통한 병원 재정 관리 및 수납 업무 효율화 방향 | 청구·결제·환불의 연결과 대사, 복수거래의 구성 | 진료 단위 통합 확인과 재확인 절차 검토 |

네 관점은 **기준정보 통합 → 접수 → 진료 → 수납**이라는 외래 진료 흐름으로 연결됩니다. 개별 지표를 곧바로 운영 원인으로 단정하지 않고, 관측 사실과 개선 제안을 구분합니다.

## 2. 데이터

### 2.1 데이터의 성격과 구조

수도권 종합병원 환경을 재현한 **실습용 합성 외래 EMR 데이터**를 사용합니다. 실제 환자·병원의 운영 성과로 일반화할 수 없으며, 생성 규칙이 분포와 반복 패턴에 영향을 줄 수 있습니다.

| 항목 | 발표자료에 기재된 범위 |
| --- | --- |
| 원천 데이터 규모 | 약 1,157만 건 |
| 데이터 구조 | 17개 테이블, 119개 컬럼 |
| 의료기관 | 490개소 |
| 의료진 | 전문의 4,748명 |
| 분석 기간 | 2023년 1월~2025년 12월 |
| 정제 데이터 스키마 | `team3_medallion` |
| 품질 검토·격리 스키마 | `team3_medallion_dq` |

위 규모는 최종 발표자료의 데이터 개요에 기재된 값입니다. 원천 규모와 정제 후 분석 모집단은 다르며, 소주제별 지표는 해당 추출 조건과 분모를 따릅니다.

#### 주요 도메인과 테이블

| 도메인 | 주요 테이블 | 주요 정보 |
| --- | --- | --- |
| 의료기관·의료진 | `hospitals`, `hospital_departments`, `departments`, `doctors`, `doctor_assignments` | 병원·진료과 기준정보, 의사 소속·배치와 유효기간 |
| 외래 세션·예약 | `clinic_sessions`, `appointment_slots`, `appointments`, `appointment_events` | 운영 세션, 예약 슬롯, 예약 상태와 변경 이력 |
| 접수·진료 | `patients`, `checkins`, `encounters`, `encounter_services` | 환자 기준정보, 도착·접수 결과, 진료 시각, 서비스 상세 |
| 서비스·수납 | `service_catalog`, `payments`, `refunds`, `ext_code_dictionary` | 서비스 가격 버전, 결제·환불, 원천 코드 매핑 |

#### 데이터 연결 흐름

```text
병원·진료과·의사 기준정보
        │
        └─ 외래 세션 ─ 예약 슬롯 ─ 예약·예약 이벤트
                │
환자 ───────── 접수 ─ 진료 ─ 진료 서비스 상세
                       │            │
                       │       서비스 가격 버전
                       │
                       └─ 결제 ─ 환불
```

외래 흐름을 설명한 개념도입니다. 모든 방문이 예약을 거치는 것은 아니며, 실제 조인은 테이블별 기본키·외래키와 업무 규칙을 따릅니다. 진료·서비스·결제처럼 일대다 관계가 있는 데이터는 각각 집계한 후 연결해 중복 합산을 방지합니다.

### 2.2 데이터 정제 방법

명세서와 ERD의 키·자료형·업무 규칙을 기준으로 데이터를 점검합니다. 복구 가능한 표기 차이는 표준화하고, 근거가 부족하거나 참조 관계를 확인할 수 없는 기록은 정상 데이터에 억지로 포함하지 않습니다.

| 점검 영역 | 주요 확인 사항 | 처리 원칙 |
| --- | --- | --- |
| 식별자·참조 무결성 | 기본키 중복·충돌, 필수키 결측, 부모 레코드 존재 여부 | 동일 내용 중복과 키 충돌을 구분하고 검토·제외 사유 기록 |
| 날짜·시간 정합성 | 도착·접수·진료 시각 순서, 유효한 날짜와 세션 범위 | 명세서가 허용하는 표기만 표준화하고 불가능한 값은 검토 대상으로 분리 |
| 기준정보 표준화 | 성별·예약 채널·서비스 분류 등 원천 코드 차이 | 명시적 매핑으로 통합하고 미등록·충돌 코드는 별도 확인 |
| 진료·금액 교차검증 | 접수 결과와 진료 연결, 서비스 단가·상세합, 결제·환불 관계 | 독립된 근거를 대조하고 상충하거나 불충분한 값은 임의 보정하지 않음 |
| 운영·중복 거래 점검 | 비정상 운영 시각, 중복 예약·거래, 업무상 허용 범위 | 업무 규칙에 따라 분류하고 검토 대상과 중복 제외 이력 보존 |

발표자료는 이러한 정제 범주를 **16대 무결성 정제 로직**으로 요약합니다. 저장소의 노트북별 세부 판정과 출력은 각 코드의 구현을 기준으로 확인합니다.

#### 사용 도구

| 도구 | 역할 |
| --- | --- |
| Python·Jupyter Notebook | 데이터 점검, 정제 로직 실행, 결과 확인 |
| Polars | 대용량 CSV 처리와 집계·조인 |
| Pandas·NumPy | 조건별 정제, 코드 표준화, 검증 및 분석 |
| MySQL·SQL | 정제 데이터 조회와 주제별 분석 데이터 추출 |
| SQLAlchemy | 발표자료에 제시된 DB 연계·적재 도구 |

일부 정제 노트북은 CSV 생성까지 수행하고 DB 적재는 수행하지 않습니다. 각 노트북의 실행 범위와 경로를 확인한 후 사용합니다. 처리 속도·메모리 개선 배수는 별도 벤치마크 근거가 필요하므로 여기에 성과 수치로 제시하지 않습니다.

### 2.3 정제 결과와 정합성 확인

아래는 **최종 발표자료 2.3절에 제시된 정제·격리 결과**입니다. 테이블별 집계이므로 격리율을 단순 평균해 전체 데이터의 격리율로 사용하지 않습니다.

| 테이블 | 정제 적재 | 격리 분리 | 격리율 |
| --- | ---: | ---: | ---: |
| `encounters` | 488,684건 | 240,240건 | 33.0% |
| `encounter_services` | 1,499,018건 | 559,497건 | 27.2% |
| `checkins` | 829,165건 | 220,378건 | 21.0% |
| `appointment_slots` | 983,834건 | 207,593건 | 17.4% |

- **정상·검토 데이터 분리:** 정제 데이터와 품질 검토 대상을 구분해 관리합니다. 격리 데이터는 분석 모집단에 임의로 복원하지 않습니다.
- **참조 관계 확인:** 발표자료는 정제 DB의 19개 물리 외래키 참조 무결성을 100%로 제시합니다. 이는 해당 검증 범위의 결과이며 모든 업무 규칙이 자동으로 충족된다는 의미는 아닙니다.
- **연쇄 영향 점검:** 상위 접수·진료 기록의 오류가 서비스 상세·수납에 미치는 영향을 함께 확인합니다.
- **처리 이력 보존:** 검토 대상과 중복 제외 기록을 구분하고, 원천 위치와 처리 사유를 남깁니다.
- **분석 기준 고정:** 정제 후에도 소주제별 기간·대상·단위를 명시하고, 같은 업무 기록이 조인으로 증가하거나 여러 집계에서 중복 합산되지 않도록 점검합니다.
